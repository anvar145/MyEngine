# Редактор MyEngine — устройство и руководство

Редактор — **отдельное приложение**: он импортирует движок (`engine.*`), но
движок о нём не знает. Поэтому плеер и headless-рендер по-прежнему собираются
без PySide6.

```bash
.venv\Scripts\python.exe main.py                              # запуск (точка входа верхнего уровня)
.venv\Scripts\python.exe main.py --language en                # английский интерфейс
.venv\Scripts\python.exe main.py --quality low                # слабое железо
.venv\Scripts\python.exe main.py --script scripts/spin_demo.py --run   # сразу открыть и запустить скрипт
.venv\Scripts\python.exe main.py --screenshot _work/editor.png   # снимок интерфейса
.venv\Scripts\python.exe editor\main.py                       # то же через пакет редактора
.venv\Scripts\python.exe scripts\run_editor.py                # то же из каталога scripts
```

`main.py` в корне — тонкая обёртка: он собирает `QApplication`, тему, контекст
редактора и главное окно. `editor/main.py` делает то же самое, но как
самостоятельную точку входа пакета `editor`.

Ключи командной строки: `--project` (корень проекта для панели ассетов),
`--language {ru,en}`, `--quality {low,medium,high}`, `--width/--height`,
`--screenshot` + `--frames` (снять PNG без участия пользователя), `--verbose`.

## 1. Структура пакета

| Файл | Ответственность |
|---|---|
| `editor/main.py` | точка входа: правит `sys.path` и вызывает `editor.app.main` |
| `main.py` | точка входа верхнего уровня: приложение, тема, окно, панель скриптов |
| `editor/app.py` | `QApplication`, формат GL-поверхности, тема, аргументы, скриншот-режим |
| `editor/main_window.py` | `QMainWindow`: меню, тулбары, доки, статусбар, команды, раскладка |
| `editor/context.py` | `EditorContext` (сцена, ресурсы проекта, переводчик) и `SelectionModel` |
| `editor/panels/` | панели: `hierarchy`, `inspector`, `camera_panel`, `assets`, `console`, `stats`, `script_editor` (+`code_editor`, `find_replace`), общий `base` |
| `editor/viewport/` | `EditorViewport`: встраивание рендерера движка, связь со сценой и гизмо камер |
| `editor/gizmos/` | гизмо в сцене: `CameraGizmo` — иконка камеры, фрустум и выбор мышью |
| `editor/models/` | `SceneTreeModel` — дерево объектов прямо над ECS-сценой |
| `editor/widgets.py` | переиспользуемые виджеты: `VectorEditor`, `ColorButton`, `SectionBox` |
| `editor/theme/` | токены палитры, `dark.qss`, загрузка SVG-иконок |
| `editor/i18n/` | `Translator` и словари `ru.json` / `en.json` |
| `editor/project_manager.py` | окно менеджера проектов при запуске (`ProjectManagerDialog`, `choose_project`, `resolve_launch_project`) |
| `editor/scene_io.py` | сохранение и загрузка сцен в JSON |
| `engine/scripting/` | `ScriptRuntime`, `ScriptComponent`, подсветка синтаксиса — движок, без Qt |
| `editor/tests/` | тесты: локализация, сцена, окно, панели, камеры, редактор кода, скрипты |

Правило зависимостей: панели знают только про `EditorContext`, окно — про
панели, а вьюпорт — про `engine.rendering`. Никто, кроме `EditorViewport`, не
обращается к OpenGL.

## 2. Окно и док-панели

Главное окно собрано из `QDockWidget`: панели перетаскиваются, отстыковываются
в отдельные окна, закрываются (их возвращает меню «Вид»), а раскладка
сохраняется между запусками через `QSettings` (геометрия, состояние доков,
выбранный язык). Кнопка «Сбросить раскладку» возвращает исходное размещение.

Раскладка по умолчанию:

```
┌───────────────┬──────────────────────────────┬───────────────┐
│ Иерархия      │ [Сцена 1*] [Сцена 2] [+]     │ Инспектор     │
│ Ассеты /      │         Вьюпорт (3D)         │ (объект,      │
│ Статистика    │     превью камеры — в углу   │ камера, свет) │
├───────────────┴──────────────────────────────┴───────────────┤
│ Консоль                                                       │
└───────────────────────────────────────────────────────────────┘
```

Меню: **Файл** (новая сцена, открыть, сохранить, сохранить как, открыть/новый
проект, недавние, выход), **Правка** (дублировать, удалить, снять выделение),
**Создать** (куб, сфера, плоскость, пустой объект, камера, четыре типа света —
единственное место создания камер и света), **Скрипты**, **Вид** (приблизить к
выбранному, сбросить камеру, гизмо и фрустумы камер, гизмо источников света,
панели, сбросить раскладку), **Язык**, **Справка**. Отдельного меню «Проект» нет:
его пункты перенесены в «Файл».

Над вьюпортом — **вкладки сцен** (`SceneTabs`, `SceneDocument`): одна вкладка на
открытую сцену, `*` у несохранённой, крестик спрашивает Сохранить/Отбросить/
Отмена, «+» создаёт новую. Каждая вкладка помнит путь и вид камеры редактора.
Двойной клик по `*.scene.json` в «Ассетах» открывает сцену во вкладке (или
переключает на уже открытую). При смене вкладки скрипты останавливаются.

## 3. Панели

**Иерархия** — `QTreeView` над `SceneTreeModel`, который читает иерархию прямо
из ECS (`GameObject.parent` / `children`), поэтому в дереве всегда реальное
состояние движка. Есть поиск по подстроке (с учётом вложенности), подсветка
неактивных объектов, двойной клик — переименование, контекстное меню —
дублировать/удалить/снять выделение, `Delete` — удалить, `F` — приблизить.

**Инспектор** — секции «Объект», «Трансформ» и компонентов (MeshRenderer,
камера, свет, скрипты):

* имя, тег, флаг активности;
* позиция, поворот (в градусах Эйлера, конвертируется в кватернион) и масштаб —
  три поля на вектор (`VectorEditor`; подписи X/Y/Z — отдельные цветные метки,
не часть поля). Колесо мыши меняет значение только у поля в фокусе: сначала
клик, потом прокрутка;
* параметры `MeshRenderer`: меш (`QComboBox`), цвет (`ColorButton` с
  `QColorDialog`), шероховатость, металличность, видимость.

Значения применяются сразу — изменения видны во вьюпорте без подтверждения.
Если у объекта нет `MeshRenderer`, инспектор предлагает добавить компонент.

**Ассеты** (вкладкой рядом со «Статистикой») — `QFileSystemModel` + `QTreeView`
с фильтром по категориям (все файлы, модели, текстуры, сцены, скрипты). Двойной клик по модели (`.obj`, `.glb`,
`.gltf`, `.fbx`) добавляет объект в сцену.

**Консоль** — перехватывает логи движка и редактора через собственный
`logging.Handler`, поддерживает фильтр по уровню (`DEBUG…ERROR`), подсветку по
уровню и очистку. Ошибки скриптов и сообщения рендерера видны здесь же.

**Статистика** — сцена (объекты, компоненты, активные, системы), рендерер
(вызовы отрисовки, пачки, треугольники, экземпляры, отсечённые), FPS, камера
(позиция, дистанция) и строка драйвера. Обновляется таймером 400 мс.

**Камера и свет** — отдельных панелей нет: свойства показывает инспектор
выбранного объекта в секциях компонентов (`camera_section.py`,
`light_section.py`; реестр компонентов в `inspector.py`):

* «Проекция»: включённость, порядок, тип, FOV, высота ортографии, near/far;
  «Вьюпорт и очистка»: прямоугольник, aspect, цвет фона, флаги очистки, маска
  слоёв;
* «Источник света»: цвет, интенсивность, радиус и затухание, углы конуса,
  параметры теней у солнца, маска слоёв. Направление света задаётся поворотом
  объекта (свет светит вдоль локальной `+Z`);
* камера-объект независима от камеры редактора: она рисуется собственным
  `CameraPreview`, не меняя вид и тени основного окна;
* **превью выбранной камеры** — рамка в правом нижнем углу вьюпорта с именем
  камеры; текстура рисуется напрямую, обновление ограничено по частоте;
* камера и свет сериализуются в сцену и копируются при дублировании.

Секции применяют значения сразу; инспектор не перестраивается во время правки
поля, чтобы не терять фокус.

**Физика** (`panels/physics_sections.py`): секции `RigidBodyComponent`,
`ColliderComponent` и `CharacterControllerComponent`, добавляются через «Добавить
компонент». У контроллера персонажа:

* геометрия и слои — `radius`, `height`, `step_offset`, `slope_limit`,
  `skin_width`, `layer`, `mask` (маска вводится hex-строкой, 32 бита);
* движение — `move_speed`, `sprint_multiplier`, `jump_velocity`, `use_gravity`,
  `gravity_scale`, `ground_check_distance`, `air_control`, `snap_to_ground`,
  `alignment_to_ground`; у каждого поля подсказка, границы виджета совпадают с
  допустимыми значениями компонента (`clamp_character_field`), так что ввод вне
  диапазона до компонента не доходит. Движение, гравитация и земля — «живые» поля:
  правка во время игры не пересоздаёт двойника и не сбрасывает вертикальную скорость.

**Заголовок секции.** У секций `RigidBody`, `Collider` и `CharacterController` в
заголовке (`SectionBox.add_header_controls`, `editor/widgets.py`) стоят галочка
«Включён» и кнопка «Удалить»:

* «Включён» меняет `component.enabled`, помечает сцену изменённой и обновляет
  подписи конфликта у соседних секций. У контроллера выключение — режим
  **«заморожен»**: двойник остаётся в мире, но не двигается (`docs/CORE.md` §7.2),
  поэтому подсказка у галочки объясняет это. Секция выключенного компонента
  выделена серой полосой у левого края заголовка и приглушённым названием
  (динамическое свойство `frozen` в стиле `QFrame[role="sectionHeader"]` /
  `QLabel[role="section"]` в `dark.qss.tpl`); поля остаются доступными, их можно
  править до включения.
* «Удалить» снимает компонент (`remove_component`) **после подтверждения**
  (`QMessageBox.question`, по умолчанию «Нет»): в редакторе пока нет undo/redo
  для компонентов, отменить удаление нельзя. После удаления инспектор
  перестраивается, сцена помечается изменённой, в статус-строке появляется
  сообщение; двойник контроллера (в том числе замороженный) из мира уходит.

Начало координат объекта с контроллером — центр капсулы, в покое он на
`height/2 + skin_width` над землёй. Меш с началом у ступней делайте **дочерним**
объектом со смещением `y = -(height/2 + skin_width)` (для умолчаний `−0.92`): на
центре капсулы ступни окажутся на высоте `height/2` над полом. Одновременно
`CharacterControllerComponent` и `RigidBodyComponent` на объекте не работают
(`docs/CORE.md` §7.2): если активны оба, у секций контроллера и твёрдого тела под
заголовком появляется красная подпись «Конфликт: CharacterController и RigidBody
несовместимы» (`inspector.physics.conflict.cc_rb`). Подпись только сообщает —
редактирование не блокируется; при выключении или удалении одного из компонентов она
гаснет у второго без пересборки инспектора. Выключенный компонент не конфликтует
(та же проверка `has_character_rigidbody_conflict`, что у адаптера физики).

**Масштаб персонажа.** `radius`/`height` умножаются на мировой масштаб объекта (с
учётом родителей): `radius × max(|sx|, |sz|)`, `height × |sy|` (`docs/CORE.md` §7.2,
«Масштаб объекта»). Объект `(2, 2, 2)` с умолчаниями получает капсулу r 0.8 / h 3.6, `(2, 1, 2)` — 0.8 / 1.8.
`skin_width`, `step_offset`, `ground_check_distance` и скорости масштабом не
затрагиваются. Если после масштаба `height ≤ 2·radius` (`(4, 1, 4)`), высота
поднимается до `2·radius + ε` с предупреждением в логе, а не ошибкой. Ступни остаются на месте при смене размера:
центр капсулы сдвигается на половину изменения высоты.

Смещение дочернего меша с началом у ступней при масштабе корня (или родителя) — в
локальных единицах ребёнка. Пусть `sy` — мировой масштаб по вертикали, `H = height·sy` —
итоговая высота капсулы, тогда `y = -(H/2 + skin_width) / sy`; знаменатель нужен,
потому что масштаб родителя умножает и смещение ребёнка. При `sy = 1` формула
сводится к `-(height/2 + skin_width)` (`−0.92` для умолчаний).

**Гизмо источников света** (`editor/gizmos/light_gizmo.py`) рисуются во
вьюпорте:

* иконка — каркасный ромб постоянного экранного размера: свет не имеет
  габаритов, и иконка фиксированного мирового размера терялась бы вдали;
* зона влияния — три кольца радиуса действия у точечного света и конус у
  прожектора. Показывается у выделенного источника или по флагу меню: иначе
  десяток конусов закрыл бы сцену;
* лучи направления — у солнца и прожектора («гребёнка» со стрелками).

Клик по иконке выбирает объект-владелец; гизмо получает клик раньше орбиты,
причём камеры проверяются первыми — их иконки крупнее.

**Редактор скриптов** — «маленькая IDE» внутри редактора (скрыта по умолчанию,
включается `Ctrl+Shift+E` или меню «Скрипты»):

* слева — дерево папки `scripts/` проекта (с подпапками, только `*.py`);
  «Создать» кладёт файл в выделенную папку с уникальным именем
  (`new_script.py`, `new_script_2.py`…); закрытие вкладки и окна спрашивает
  про несохранённые изменения;
* справа — вкладки открытых файлов и консоль скриптов снизу. Вкладка помечается
  `●`, пока файл отличается от версии на диске;
* тулбар: создать, открыть, сохранить, сохранить всё, запустить, остановить,
  перезагрузить и «Найти и заменить».

Каждая вкладка — `CodeEditor` (`QPlainTextEdit`) с нумерацией строк, подсветкой
синтаксиса (`PythonHighlighter`), моноширинным шрифтом (JetBrains Mono, затем
Cascadia/Consolas/DejaVu), автоотступом после `:`, снятием отступа после
`return`/`pass`/`break`/`continue`/`raise`, Tab/Shift+Tab по выделению, умным
`Backspace`, автозакрытием и подсветкой парных скобок, `Ctrl+/` для
комментирования и `QCompleter` (ключевые слова, встроенные имена, публичный API
движка и имена из самого файла; список открывается по `Ctrl+Space` или сам при
наборе двух символов).

`ScriptRunner` держит реестр `ScriptRuntime`, каждые 16 мс вызывает `on_update`
у компонентов-скриптов сцены и раз в ~700 мс проверяет время изменения файлов:
изменённый файл перезагружается, компонент получает `on_destroy` от прежней
версии и `on_start` + `on_reload` от новой. Кнопка «Стоп» (и `Shift+F5`)
вызывает `on_destroy` у **всех** скриптов и очищает реестр.

Запуск (`F5`) работает в двух режимах: если скрипт открыт во вкладке, он
выполняется разово без объекта сцены (удобно для проверки логики), а
компоненты сцены начинают тикать. Кнопка «Добавить скрипт» в инспекторе
открывает встроенный выбор (`script_picker.py`: только `scripts/` и подпапки) и добавляет `ScriptComponent` выделенному объекту —
тогда `on_update` вызывается каждый кадр.

**Импорт ассетов.** `EditorContext.start_imports()` создаёт `AssetDatabase`
(источники — `assets_root_for(project_root)`, кэш — `<проект>/Library`) и
`ImportManager`; `QTimer` каждые 500 мс вызывает `poll()`, события менеджера
превращаются в сигналы `imports_changed` / `imports_restarted`. Запуск явный
(тесты и скрипты не создают `.meta` сами); `main.py` и `editor.app` запускают его
сразу, если не передан `--no-import`. **Внимание:** проект по умолчанию — корень
репозитория, поэтому запуск без `--project` создаёт `.meta` в `assets/`.
Смена проекта перезапускает менеджер; `closeEvent` его останавливает.

**Кэш шейдеров.** При включённом импорте `ViewportWidget` получает рендерер с
`program_cache_dir = <проект>/Library/ShaderCache` (`EditorContext.shader_cache_dir`):
двоичники `glGetProgramBinary` пишутся лениво, повторный запуск пропускает компиляцию.
С `--no-import` кэш отключён. `gc_library()` каталог кэша не трогает.

**GUID мешей в сценах.** `save_scene(scene, path, assets)` пишет рядом с `mesh` ещё и
`mesh_guid` (для не встроенных мешей, зарегистрированных в базе); `load_scene(path,
assets)` по GUID находит актуальный путь, если файл переименовали или перенесли. Старые
сцены без GUID и неизвестные GUID читаются по пути. Смена меша в инспекторе обнуляет
GUID.

* Панель **Импорт** (`panels/import_manager.py`, нижний док рядом с консолью):
  таблица «путь / импортёр / состояние», фильтр по состоянию, кнопки
  «Переимпортировать выбранный / все», «Очистить Library» (с подтверждением),
  текст ошибки с копированием, прогресс-бар и сводка. Обновляется с
  дебаунсом 80 мс.
* **Инспектор ассета**: клик по файлу в панели ассетов снимает выделение объекта и
  показывает `ImportSettingsSection` — форму, построенную по `settings_schema`
  импортёра (bool/int/float/choice/str; списки — JSON-строкой), кнопки
  «Применить» (`set_settings`, в `.meta` пишутся только отличия от умолчаний),
  «Сбросить», «Переимпортировать». Выбор объекта форму скрывает.
* **Панель ассетов**: `*.meta` скрыты; файлы в очереди помечены `…`, упавшие —
  красным с текстом ошибки в подсказке; перетаскивание файлов из проводника
  копирует их в выбранную папку (имена не перезаписываются: `name (1).ext`) и
  сразу регистрирует через `poll(force=True)`.
* В статусбаре — прогресс текущей пачки импорта (скрыт, пока пачки нет).

## 4. Вьюпорт

`EditorViewport` встраивает движковый `ViewportWidget` (`QOpenGLWidget`) в
центральную область и превращает ECS-сцену в список объектов отрисовки:

* для каждого объекта с активным `MeshRenderer` берётся GPU-меш (встроенный
  `cube`/`sphere`/`plane` или файл ассета) и материал из кэша;
* выделенный объект подсвечивается акцентным цветом и получает каркасную рамку
  (`wire_box_mesh`) вокруг своих габаритов;
* сетка редактора рисуется линиями тем же рендерером;
* камеры сцены получают гизмо: иконка постоянного экранного размера (каркасный
  куб с «объективом»), а у выделенной камеры дополнительно рисуется усечённый
  объём по `camera.frustum_corners()`. Фрустум всех камер включается галочкой в
  меню «Вид»;
* кэши мешей, материалов и гизмо переживают кадры, а при открытии другой сцены
  сбрасываются.

Управление камерой: **Alt+ЛКМ** (или ЛКМ) — орбита, **ПКМ/СКМ** — панорама,
**колесо** — зум (шаг не затухает у цели: камера проходит сквозь неё),
**W/E/R** — гизмо перемещения/поворота/масштаба выбранного объекта (ось X
красная, Y зелёная, Z синяя; перетаскивание оси не вращает камеру), **F** — приблизить к
выбранному, **Home** — сбросить вид. **ЛКМ по иконке камеры** выбирает эту
камеру (и переключает предпросмотр) — гизмо получает клик раньше орбиты.

Положение и ориентация камеры редактора сохраняются между сессиями: JSON-файл
`<проект>/.myengine/camera.json` (`EditorCameraSession`) пишется при закрытии
окна и при смене проекта, а читается при старте.

## 5. Тема и иконки

Тёмная тёплая тема (без синих оттенков, акцент — терракот `#d97757`).
Единая точка правды — `PALETTE` в `editor/theme/__init__.py`; QSS собирается из
шаблона `editor/theme/dark.qss.tpl` подстановкой токенов `@имя` один раз при
старте (`load_stylesheet`). Никаких графических эффектов (тени/blur) — слабые iGPU.

Иконки — Lucide (ISC, `assets/icons/LICENSE-lucide.txt`), 24×24, `stroke-width` 1.75.
`editor.theme.icon(name, color=None)` перекрашивает SVG под токен палитры и кэширует
по `(name, color)`; состояния: обычное — `text`, включённое — `accent`, выключенное —
`text_dim`. Иконки панели «Ассеты» — `_LucideIconProvider`.

Левая иконочная рейка `SideRail` (`editor/widgets.py`) переключает док-панели
(Иерархия, Ассеты, Инспектор, Консоль, Импорт, Статистика) и синхронна с ними.

Анимации — `editor/anim.py` (`fade_in`, `animate_width/height`, ≤180 мс, только
геометрия/прозрачность); отключаются в offscreen и при `MYENGINE_REDUCE_MOTION=1`.

Менеджер проектов — шаблоны новых проектов в `assets/templates/` (`empty`, `3d`, `2d`).

## 6. Локализация (i18n)

Строки лежат в JSON рядом с кодом: `editor/i18n/ru.json` и `editor/i18n/en.json`
(по 238 ключей). `Translator` умеет переводить с подстановками
(`tr("status.selected", name="Cube")`), а при смене языка испускает сигнал
`language_changed`.

* Каждый виджет реализует `retranslate()` — при переключении языка **всё**
  обновляется на лету: меню, тулбар, заголовки доков, подписи инспектора,
  плейсхолдеры, статусбар.
* Язык переключается из меню «Язык» или ключом `--language` и запоминается в
  `QSettings`.
* Тесты проверяют, что наборы ключей в словарях совпадают и что нет пустых
  строк — забытый перевод сразу падает в CI, а в интерфейсе вместо текста
  показывается сам ключ.

Добавить язык: положить `editor/i18n/<код>.json`, внести код в `LANGUAGES`
(`editor/i18n/__init__.py`) и добавить ключ `menu.language.<код>` в словари.
Если понадобится Qt Linguist (`.ts`/`.qm`), меняется только загрузчик внутри
`Translator` — интерфейс `tr(...)` и сигнал остаются.

## 7. Сцены и файлы

Открытые сцены — документы-вкладки (`editor/scene_document.py`); «Сохранить» не
спрашивает путь, если он известен. Сцена сохраняется в JSON (`editor.scene_io`): формат, версия, объекты с
идентификаторами, иерархия, локальные трансформы и компоненты. Загрузка
восстанавливает иерархию вторым проходом, поэтому ссылки на родителей не
теряются, а версия формата проверяется (сцену из более новой версии редактор
открывать откажется с понятной ошибкой).

Текущий формат — **v2**: объекты адресуются стабильным `uid` (16 hex), `parent` —
`{"uid": ...}` или `null`, ссылки на объекты в полях скриптов — `{"uid": ...}`. Сцены v1
(числовые `id`/`parent`, ссылки `{"object": id}`) читаются; uid им выдаётся
детерминированно (`migrated_uid`), сам файл при открытии не меняется. При первом сохранении
v1-файла на месте рядом создаётся копия `<имя>.v1.bak` (один раз, не перезаписывается).
Подробности — `docs/CORE.md` §2.

```json
{
  "format": "myengine.scene",
  "version": 2,
  "name": "Scene",
  "objects": [
    {
      "uid": "9f3c1a07b2d84e55", "name": "Cube", "parent": null, "active": true,
      "transform": {"position": [0, 0.5, 0], "rotation": [0, 0, 0, 1],
                    "scale": [1, 1, 1]},
      "components": [{"type": "MeshRenderer", "mesh": "cube",
                      "color": [0.87, 0.58, 0.24], "roughness": 0.5}]
    }
  ]
}
```

## 7a. Менеджер проектов

При запуске без `--project` сначала показывается `ProjectManagerDialog` (`editor/project_manager.py`), и только после выбора создаётся главное окно. Окно не показывается при `--project`, `--no-launcher` и `--screenshot`.

- Список проектов из `projects/` (`list_projects`): имя, дата изменения, число сцен; поиск по имени, сортировка (последний открытый / дата / имя); карточка выбранного проекта.
- Создание: имя проверяется на лету (`validate_project_name`, занятое имя), затем `create_project` и открытие.
- Открытие: кнопка, двойной клик или Enter. Контекстное меню: «Показать в проводнике», «Удалить…» (подтверждение вводом имени; удаляются только папки прямо в `projects/`).
- Язык ru/en переключается в окне; последний проект, язык и флаг «открывать последний проект при запуске» хранятся в `QSettings` (`launcher/*`). Закрытие окна без выбора завершает приложение.
- `EditorContext(project_root=…, workspace_root=…)`: `workspace_root` — репозиторий с папкой `projects/`, поэтому внутри проекта вложенная `projects/` не создаётся.

## 7b. Раскладка проекта, меню компонентов, Script Editor

- **Раскладка проекта** (только она, плоские проекты не поддерживаются): `<Project>/{Assets/{Audio,Materials,Models,Scenes,Scripts,Shaders,Sprites,Textures}, Library, Settings, <Name>.project.json}`. Пути берутся из хелперов `editor/project.py`: `assets_root_for`, `scripts_root_for`, `scenes_root_for` (в `.project.json` сцена хранится как `Assets/Scenes/main.scene.json`). Шаблоны `assets/templates/{2d,3d}` лежат в той же раскладке. Менеджер проектов считает сцены и скрипты внутри `Assets/Scenes` и `Assets/Scripts`.
- **Имена создаваемых объектов** всегда английские (`Camera`, `Directional Light`, `Cube`…) и не зависят от языка интерфейса; повтор получает суффикс `Cube (1)` (`unique_object_name` в `editor/context.py`).
- **Поля `VectorEditor`/числовые поля**: поля осей одной ширины; клик в поле выделяет всё содержимое (`FocusDoubleSpinBox`/`FocusSpinBox`, выделение откладывается на следующий цикл событий).
- **Меню «Добавить компонент»**: подменю-группы Рендеринг / UI / Освещение / Физика (таблица `COMPONENT_GROUPS` в `inspector.py`, у каждого пункта и группы своя иконка Lucide). Уже имеющиеся на объекте компоненты показываются серыми с подсказкой причины (`inspector.component.*`); RigidBody и CharacterController взаимно блокируют друг друга.
- **Script Editor**: дерево показывает только `Assets/Scripts` (включая подпапки); подпапку создаёт кнопка в заголовке дерева или пункт контекстного меню. «Новый скрипт» открывает вкладку без записи на диск — файл появляется по Ctrl+S (путь предлагается в выбранной папке), закрытие неподписанной вкладки спрашивает о сохранении.
- **Размер окна**: после восстановления геометрии окно вписывается в `availableGeometry()` экрана; панель статистики прокручивается.

## 7c. Undo/redo

Правки сцены отменяются Ctrl+Z, повторяются Ctrl+Y / Ctrl+Shift+Z (меню «Правка»).
История — `CommandStack` из `engine/core/commands/` (`SceneDocument.commands`, лимит 200
записей, см. `docs/CORE.md` «Команды отмены»): каждая правка — команда (создание/удаление,
rename, reparent с позицией среди братьев, компоненты, поля, поля скриптов, пересборка
экземпляров префабов, Unpack, «Сохранить как префаб»), запись пропорциональна правке, а не
сцене. Несколько действий одной операции (drag 50 объектов, перемещение мультивыделения) —
одна запись через `EditorContext.transaction`. Правки одного поля в окне 1 с сливаются;
поля скриптов — по ключу компонент + поле. Идентичность объектов — `uid`: выделение после
undo/redo восстанавливается по `uid`. `notify_modified()` шаг не создаёт.
Dirty-флаг = «состояние не совпадает с сохранённым». В Play Mode недоступно.
Ограничения: ссылки полей *других* скриптов на удалённый объект после undo не
восстанавливаются; порядок `scene.objects` после undo удаления может отличаться (порядок
братьев сохраняется); undo «Применить к префабу» откатывает только сцену, файл префаба
остаётся изменённым; `delete_objects` уничтожает объекты сразу, поэтому во время
`scene_modified` в выделении ещё могут быть уничтоженные объекты — подписчики пропускают
`is_destroyed`. Файлы и настройки вне сцены не откатываются. Снимки сцены остались только в
Play Mode (`SceneSnapshot`).

## 7d. Поля скриптов

Под строкой скрипта в инспекторе — секция `ScriptFieldsForm` (`editor/panels/script_fields.py`)
с полями из `scan_fields`: spin для int/float, флажок, строка для str, `ReferenceField` для
объекта/файла (принимает drop; MIME объекта — `editor/mime.py`, иерархия — `mimeData` модели
и `DragOnly`; файлы — `uri-list` от `QFileSystemModel`, панель ассетов `DragOnly`). Правка
вызывает `notify_modified()`, поэтому попадает в undo/redo. Подробности — `docs/SCRIPTING.md`.

### ReferenceField для AssetRef (A6)

`ReferenceField("asset")` (`editor/panels/script_fields.py`) показывает `AssetRef`:
имя файла (или имя примитива), в tooltip — путь и GUID; «×» очищает; нерезолвимая ссылка
(`ref.resolve(asset_db)` → `None`) — красная метка (`role=error`). Drop файла из панели
ассетов превращается в `AssetRef` через `make_asset_ref(db, path)` (GUID из базы, путь от
`Assets/`). Поле используется в `ScriptFieldsForm` (kind `asset`) и для меша
`MeshRenderer`: принимает файлы `.obj/.gltf/.glb/.fbx`, кнопка «▾» — выбор примитива,
«×» возвращает `cube`.

## 7e. Префабы (A4.2)

«Создать -> Префаб...» (`MainWindow.create_prefab`) открывает диалог `*.prefab.json`
(старт — `Assets/`), строит `make_prefab_loader(asset_db, project_root)`, ставит его в
`scene.prefab_loader` (снимок undo теряет загрузчик, поэтому выставляется перед каждым
instantiate) и создаёт экземпляр; ошибки (`PrefabError`, `OSError`) уходят в статус-строку.
У корня экземпляра инспектор показывает read-only секцию `PrefabInstanceSection`
(`editor/panels/prefab_section.py`): GUID, путь, состояние (без изменений / изменён) и
список overrides. «Сохранить как префаб», drag-and-drop, Unpack — A4.5 (ниже).

### Overrides в инспекторе (A4.3)

* Выбранный объект — корень или член экземпляра (`find_instance`): значения, заданные
  override, подписаны **жирным** (Имя/Тег/Активен, Трансформ, MeshRenderer, авто-секции);
  у секции в заголовке тоже жирный шрифт. У корня секция «Префаб» показывает все overrides
  экземпляра, у члена — только его.
* У каждой записи две кнопки: «Вернуть» (`revert_instance_override`, значение из префаба) и
  «Применить к префабу» (`apply_override_to_prefab`: пишет `*.prefab.json` и пересобирает все
  экземпляры сцены с сохранением их overrides; синхронно в главном потоке, прогресс — в
  статус-строке, при > 20 экземпляров (`REBUILD_WARN_THRESHOLD`) — предупреждение). Устаревшие
  (stale) записи показаны красным без кнопок.
* «Применить к префабу» — одна запись undo (`ReplaceSubtreesCommand`), порядок среди
  братьев сохраняется; файл префаба undo не откатывает. Удаление компонентов/объектов
  экземпляра не поддерживается — для этого Unpack.
* Иерархия: у корня экземпляра иконка Lucide `package`; цвет — акцент при наличии overrides,
  приглушённый без них (`SceneTreeModel.set_instance_state_provider`).

### Редактор префабов (A4.5)

* **Сохранить как префаб** — контекстное меню иерархии, один выделенный корень (иначе
  предупреждение «выделите один корень»). Диалог пути (по умолчанию
  `Assets/Prefabs/<имя>.prefab.json`, `prefabs_root_for`), затем `save_as_prefab`
  (`engine/prefab_save.py`): файл + регистрация в `AssetDatabase` + экземпляр на месте
  оригинала (тот же родитель/трансформ/имя), выделение переносится на него. Объект, входящий
  в экземпляр другого префаба, сохранить нельзя (сначала Unpack). Ограничения: `uid` объектов
  нового экземпляра другие (выводятся из `instance_uid`, A4.1); экземпляр встаёт последним
  среди братьев. **Внешние ссылки перепривязываются**: поля скриптов (живые и ещё не
  разрешённые `{"uid"}`) и `value` в overrides других экземпляров, которые указывали на
  объекты поддерева, переводятся на соответствующие объекты экземпляра (сопоставление по
  порядку детей; ветка с расхождением имён/числа детей пропускается). Ссылки изнутри
  поддерева уходят в префаб как `local`.
* **Drag-and-drop.** Панель ассетов отдаёт для `*.prefab.json` MIME
  `application/x-myengine-prefab+json` (`editor/mime.py`, данные — путь) вместе с `uri-list`.
  Иерархия (`_HierarchyTree`, перестановки по-прежнему нет) принимает только этот MIME:
  бросок на объект — экземпляр становится его ребёнком, на пустое место — корнем сцены.
  Вьюпорт (`EditorViewport.drop_prefab`): луч из камеры редактора; попадание в AABB меша —
  точка попадания, иначе плоскость y=0, если луч смотрит вверх мимо плоскости — 10 м от
  камеры. Низ мировой AABB мешей экземпляра ставится на точку (без мешей — центр в точке).
* **Undo и выделение.** История хранит выделение как `uid` (`HistoryEntry.selection:
  tuple[str, ...]`), после undo/redo объекты находятся `scene.find_by_uid`; отсутствующих в
  снимке не выделяем.
* **Команды экземпляра** (контекстное меню иерархии, работают и для члена экземпляра — корень
  ищется вверх, `find_instance_root`): «Открыть файл префаба», «Применить всё к префабу»,
  «Вернуть всё из префаба», «Разъединить префаб (Unpack)» (подтверждение `QMessageBox.question`).
  Unpack снимает `PrefabInstance` с корня; значения (в том числе overrides) остаются в
  объектах, `uid` те же, вложенные экземпляры остаются самостоятельными экземплярами;
  операция попадает в undo. Подсказка узла содержит `prefab: <имя файла>`.
* **«Открыть префаб» не во вкладке сцены**: формат префаба (`myengine.prefab`, `local_id`)
  отличается от сцены, `scene_from_dict` его не читает, а режим «префаб во вкладке» требует
  переделки `SceneDocument` (конвертация туда-обратно и пересборка экземпляров при
  сохранении). Поэтому файл открывается во внешнем редакторе (`QDesktopServices.openUrl`);
  правки подхватываются повторной загрузкой сцены. Режим вкладки — отдельная задача.

### Настройки ввода (A5 п.3)

Панель `editor/panels/input_settings.py` (`InputSettingsPanel`) — отдельный док
справа, по умолчанию скрыт; открывается в меню «Вид → Настройки ввода».
Дерево: действие (`[kind]`, `*` — отличается от дефолта) → привязки; у привязки
кнопки «Изменить»/«Удалить», у действия «+ Привязка»/«Сбросить». Внизу
«Сбросить всё», «Загрузить», «Сохранить». «Изменить» открывает модальное окно
«Нажмите клавишу…» (клавиша или кнопка мыши, `Esc` — отмена); запись идёт через
ту же `InputState.begin_rebind`, что и в игре. «Сохранить» пишет в проект
`Settings/input.json` только отличия от дефолтов; плеер читает файл при старте,
файл другого проекта подхватывается по `project_changed`.

### Пост-процесс (A10a)

Секция инспектора «Пост-процесс» (`editor/panels/post_section.py`, `PostSection`) —
у объекта с `CameraComponent`: tonemap (linear/reinhard/aces), экспозиция, FXAA,
**bloom** (флаг, порог, сила, уровни 1–5), **виньетка** (флаг, inner/outer/сила),
**LUT** (`ReferenceField`: drop PNG 256×16 из панели ассетов, «×» очищает; сила 0..1;
в Play Mode уходит в плеер как `AssetRef.to_dict()` или `null`).
Первая правка создаёт `PostSettings.for_quality(MEDIUM)` в `SceneDocument.post`; без
правок секция `post` в сцену не пишется. Изменения сразу видны во вьюпорте
(`EditorViewport._apply_post`, `QtViewport.post_enabled`; HDR включается подсказкой
`hdr` проекта) и уходят в плеер через `send_setting("post.<имя>")`. Undo/redo-снимки и
Play Mode (`SceneSnapshot.freeze(..., sky, post)`) переносят `post`. Новый проект
получает `hdr: true` и `dynamic_resolution: true` в `*.project.json`; существующие не
меняются. Превью камеры (`CameraPreview`) идёт без поста.

### Аддитивные сцены в плеере (A8)

Плеер умеет держать рядом с основной сценой дополнительные (обе обновляются и
рисуются; UI дополнительной сцены — слоем поверх основной). Флаг
`--additive <сцена>` (можно несколько раз) загружает их после основной. Кнопка UI
(`on_click`): `load_additive:<путь>` — загрузить рядом, `unload_scene:<путь>` —
выгрузить дополнительную (активная не затрагивается). Инспектор принимает эти
префиксы. Прогресс загрузки в Play Mode: плеер шлёт IPC `scene_load_progress`/
`scene_loaded`, `EngineBridge` отдаёт сигналы `load_progress`/`scene_loaded`,
`PlayModeService` пробрасывает их в `MainWindow`, статусбар показывает
«Загрузка сцены… N%» (строка `play.loading`) до `scene_loaded`, первой статистики
плеера или выхода из Play Mode.
Ограничение: клик по кнопке дополнительной сцены проходит и в кнопки основной.

**Горячие клавиши Play Mode и Script Editor.** Дочерние окна-панели
(`WindowPanel`) с одинаковыми шорткатами в контексте `WindowShortcut` делали
F5/Shift+F5/F6 неоднозначными, и они не срабатывали. Действия панели Script
Editor теперь с `WidgetWithChildrenShortcut` (в фокусе панели действуют её
шорткаты, иначе — глобальные Play Mode). Тест: `editor/tests/test_play_shortcuts.py`.

### Mesh collider (A11)

Компонент добавляется через «Физика → Mesh collider» (`ComponentEntry` в
`inspector.py`), секция строится `AutoSection` по дескрипторам: поле `mesh` —
`ReferenceField` с фильтром `.obj/.glb/.gltf/.fbx` (перетаскивание из панели
ассетов). В отладочной отрисовке коллайдеров (F2, режимы off/selected/all) mesh
рисуется контуром: граничные рёбра и острые (> 30°) рёбра треугольников
(`physics_debug.mesh_outline`, кэш по BVH). Дублирование объекта копирует
компонент. `scene.asset_source` у сцен, загруженных из файла, выставляется
`_switch_to`; у начальной пустой сцены он появляется после первой загрузки/
переключения.
